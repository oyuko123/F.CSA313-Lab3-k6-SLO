## 1. Чанарын сценарио

### 1.1 Performance Scenariо — `/cart/add`

| Хэсэг | Тодорхойлолт |
|---|---|
| **Тойм** | Хэвийн хэрэглэгчийн ачааллын үед сагсанд бараа нэмэх API хурдан хариу өгөх шаардлагатай. |
| **Системийн төлөв** | API сервер ажиллаж, `/cart/add` endpoint хүсэлт хүлээн авч байна. |
| **Орчны төлөв** | Локал сервер дээр 20 VU тогтмол ачаалалтай, бусад endpoint-үүд мөн ажиллаж байна. |
| **Гадаад өдөөлт** | Хэрэглэгч барааг сагсанд нэмэх хүсэлт илгээнэ. |
| **Шаардлагатай хариу** | Сервер хүсэлтийг амжилттай боловсруулж HTTP 200 статус болон JSON хариу буцаана. |
| **Хэмжүүр** | `/cart/add` endpoint-ийн response time-ийн p95 нь 50 мс-ээс бага байна. |

### 1.2 Reliability Scenario — `/pay`

| Хэсэг | Тодорхойлолт |
|---|---|
| **Тойм** | Хэвийн хэрэглэгчийн төлбөр хийх үед төлбөрийн хүсэлтүүдийн ихэнх нь амжилттай байх шаардлагатай. |
| **Системийн төлөв** | API сервер ажиллаж, `/pay` endpoint төлбөрийн хүсэлтүүдийг боловсруулж байна. |
| **Орчны төлөв** | Локал сервер дээр 20 VU хэвийн хэрэглэгчийн ачаалал үүсгэж байна. |
| **Гадаад өдөөлт** | Хэрэглэгч төлбөр хийх хүсэлт илгээнэ. |
| **Шаардлагатай хариу** | Амжилттай хүсэлтэд HTTP 200 болон `paid: true` хариу буцаана. |
| **Хэмжүүр** | `/pay` endpoint-ийн HTTP error rate 8%-иас бага байна. |

### 1.3 Availability Scenario — Server Crash

| Хэсэг | Тодорхойлолт |
|---|---|
| **Тойм** | Сервер гэнэт зогссон үед дахин ажилласны дараа үйлчилгээ хэвийн үргэлжлэх шаардлагатай. |
| **Системийн төлөв** | API сервер хэвийн ажиллаж, k6 20 VU-ээр хүсэлт илгээж байна. |
| **Орчны төлөв** | 2 минутын тестийн явцад серверийг зориудаар 10 секунд зогсоож, дараа нь дахин асаана. |
| **Гадаад өдөөлт** | Серверийн гэнэтийн crash буюу ажиллагааны тасалдал үүснэ. |
| **Шаардлагатай хариу** | Сервер дахин ассаны дараа хүсэлтүүдийг дахин амжилттай боловсруулж эхэлнэ. |
| **Хэмжүүр** | Нийт хүсэлтийн амжилтын хувь 90%-иас дээш байх бөгөөд серверийн сэргэх хугацаа 10 секундээс ихгүй байна. |

## 2. SLO тодорхойлолт

Сценарио бүрийн хэмжүүрийг хэмжигдэхүйц SLO болгон тодорхойлов.

| Сценарио | SLI | Босго | Цонх / нөхцөл |
|---|---|---|---|
| Performance | `/cart/add` latency | p95 < 50 мс | 20 VU тогтмол ачаалал, 1 минут |
| Reliability | `/pay` error rate | < 8% | 20 VU, 1 минут |
| Availability | Нийт хүсэлтийн амжилтын хувь | ≥ 90% | 20 VU, 2 минут, 10 секундийн зогсолт |

### Босго сонгосон үндэслэл

- **Performance:** `/cart/add` нь локал сервер дээр маш хурдан хариулах endpoint тул 200 мс-ийн жишээ босгоос илүү нарийн 50 мс-ийн p95 босго сонгосон.
- **Reliability:** `/pay` endpoint-д ойролцоогоор 5%-ийн зориудаар үүсгэсэн алдаа байдаг тул санамсаргүй хэлбэлзлийг тооцож 8%-ийн error rate босго сонгосон.
- **Availability:** Серверийн тасалдлын үед нийт хүсэлтийн 90%-иас дээш нь амжилттай байх шаардлагатай гэж үзэж, 90%-ийн босго сонгосон.

### Availability Error Budget

Availability SLO нь 90%, тестийн цонх нь 2 минут буюу 120 секунд.
